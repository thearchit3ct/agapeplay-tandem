# Carte du backlog GitHub

Le backlog est organisé pour transformer la vision en produit testable. Les issues GitHub détaillent les tâches ; ce document garde la vue d'ensemble.

## Priorité P0 — cœur de valeur

- discovery participants, mentors et responsables ;
- gouvernance éditoriale et validation du premier parcours ;
- monorepo et CI ;
- architecture de données et RLS ;
- authentification, consentement et suppression ;
- parcours et séances ;
- binôme par invitation ;
- check-in et journal privé ;
- partage explicite ;
- communication, blocage et signalement ;
- tests cross-platform.

## Priorité P1 — pilote église

- espace mentor ;
- groupes et cohortes ;
- notifications ;
- offline et synchronisation ;
- analytics respectueuses ;
- modération et réponse aux incidents ;
- accessibilité et localisation ;
- pilote avec églises partenaires.

## Priorité P2 — expansion

- parcours personnalisés ;
- compagnon Alpha et partenariat de contenu ;
- intégration Versets Flash et Alléluia! ;
- audio ;
- familles et mineurs avec dispositif séparé ;
- abonnement église ;
- IA éditoriale encadrée ;
- intégrations partenaires.
